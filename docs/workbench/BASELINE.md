注意本轮发现并已处理的工具副作用：SQLite `mode=ro` 仍可能创建空 WAL/SHM。备份读取一度产生辅助文件；仅对清单证明原本不存在、WAL 为零字节、SHM 校验匹配且主库可独占打开的本轮文件执行移除，未移除原有侧文件。最终正式目录的文件集合、SHA-256、大小和修改时间与操作前完全一致，业务库及设置未变。以后对已生成的自包含快照做只读验证使用 `immutable=1`；不能对可能仍有待合并 WAL 的活动源库这样处理。

恢复方法：

1. 先关闭对应正式或开发实例；不要在被其他进程使用时替换数据库。
2. 从仓库外 `manifest.json` 按 SHA-256 校验选定文件；先恢复到新的空目录，恢复源码与配置，虚拟环境按锁定依赖单独重建。
3. 使用 `local/data` 内的在线 SQLite 快照恢复主库，不拼接 `raw-sidecars` 的旧 WAL/SHM。对恢复副本检查完整性、业务行数和摘要，再核对配置及外部 CAD 路径；源工程备份必须配套可用。
4. 本轮只演练了独立目录恢复。覆盖正式位置、安装或部署、凭据重新配置和真实 CAD 恢复需要另行安排；本轮未做。

备份只保存在同机仓库外，属于本轮可恢复保护，不等同于异地冷备份或完整灾难恢复。

### 功能、界面与保护

“项目文件”页从现有首页顶部按需打开。左侧项目列表和搜索，右侧文件清单、搜索/类型过滤、添加文件/目录、重新扫描、取消、关联已有零件、打开原文件和定位目录。列表含名称、类型、项目、零件编号、完整原路径（长文本悬停可看全）、大小、时间、存在/访问状态；横向内容在表格内部受限，不撑大窗口。

按扩展名识别 `.SLDPRT/.SLDASM/.SLDDRW/.STEP/.STP/.STL/.GLB/.PDF`；不解析文件内容或渲染。项目内相同规范化路径去重，同名不同目录或不同项目不误合并。文件失踪、读取失败、变成链接时保留原索引及最后已知元数据，恢复原路径后重扫可回到可用状态。

扫描和统一索引事务都在 QThread 中运行，扫描不写库或源文件；扫描后变化检测通过才提交。来源与全部文件同一事务写入，SQL 异常、事务中取消均回滚；超时、超量、深度限制或扫描取消不允许提交部分批次。成功后可重复扫描，崩溃后依赖 SQLite 事务保证恢复，已保存来源可用于重扫。

每批默认上限为 128 个来源、10,000 个目录项、15 秒、32 层；拒绝磁盘根、非绝对路径、设备路径、符号链接/目录联接/云占位、UNC 和映射网络盘。单个文件异常有明确状态或警告，不使窗口崩溃。取消在 I/O 边界检查，不能强制中断操作系统内部挂起的一次文件调用；不使用强制终止线程。
