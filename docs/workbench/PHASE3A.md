## 已实现与使用

在本阶段工作树创建项目专用Python3.12虚拟环境，按README安装基础及test依赖，然后执行：

```powershell
.\scripts\dev_snapshots.ps1
.\scripts\dev_snapshots.ps1 -DevRoot <仓库外的新专用开发目录>
.\scripts\dev_snapshots.ps1 -Smoke
.\scripts\test_workbench.ps1
```

默认数据、配置、缓存、日志和单实例标识使用`%LOCALAPPDATA%\MechanicalWorkbenchDev\phase3a`。脚本实际传递`--dev`，入口仅对隔离开发实例开放；不要用普通启动示例迁移正式库。命名、搜索、已有文件清单和预览入口保留。归档服务、单元测试和归档GUI验收不加载WebEngine、QtPdf、STEP解析器或真实CAD。

实测独立环境为CPython3.12.14、PyQt6 6.11.0、Qt运行库6.11.2、pytest8.3.5，继承已锁定依赖，无全局升级；`pip check`通过。原预览的完整回归依赖及测试生成工具按既有`setup_cad.ps1 -WithFixtures`安装，归档功能本身不需要它们。

“项目文件 → 创建本地版本 / 版本历史”：选择已有项目，指定项目根，勾选文件，确认角色及软件来源，输入版本标签/说明，再创建本地版本；可校验、恢复到新目录及查看任务记录。所有复制、哈希、校验和恢复在后台线程执行；关闭/退出会请求取消并等待任务安全退出。重启显示未完成/失败/终止任务，可恢复或终止；不会自动删除暂存或历史。

原目录扫描识别集合不扩大；归档窗口另提供明确选择附件/原生文件的入口，登记在现有`project_files`中，复用`projects.id`、`file_id`及可选零件`record_id`。`.prt`默认软件来源“未知”，可由用户标注，不猜测NX；额外附件只做文件级管理，不从旧“打开文件”入口执行未知类型。源文件、STEP/STP、GLB、PDF和附件分别标注角色，原文件名、大小写、扩展名和相对层次原样保留，不将STEP改名或用STL代替。

没有GLB/PDF也可创建仅源文件归档，选择区及历史明确提示缺少预览。额外声明的必需相对路径必须全部在本次选择中，否则拒绝。完整文件集仅指“选定文件全部完成且最近一次字节校验通过”，不代表装配引用完整。

## 三项状态分开

| 状态 | 本轮含义 |
| --- | --- |
| 字节完整性 | 对冻结清单逐文件检查大小/SHA-256、额外/缺失文件、清单与本地数据库一致性；历史显示“上次字节校验通过”，磁盘以后仍可能被篡改，应再次校验 |
| CAD装配依赖 | 始终“未验证”；不解析/打开SOLIDWORKS、NX，不验证实际装配引用，不执行宏、脚本或Pack and Go |
| 预览/PDF与源版本对应 | 始终“未验证”；文件名、时间和哈希相近都不构成对应关系证明 |

已完成版本没有应用内就地覆盖接口。新设计建立新版本；相同内容使用新任务和不同标签仍可创建，原任务重试不重复创建。项目改名通过稳定ID继续关联。磁盘写权限仍可修改归档，未提供防篡改签名或WORM保证；清单哈希的信任依据是配套的本地SQLite记录，二者一起被恶意改写不在本轮检测保证内。

## 清单、Schema与兼容

公开格式1清单含UUID任务/版本ID、现有项目ID、标签、说明、创建时间、角色、相对路径、大小、SHA-256、原文件记录/零件映射、用户软件来源、必需文件及两项未验证状态。清单中不保存源绝对路径；自由文字拒绝绝对路径。本地冻结请求、来源绝对路径、源身份/时间、任务/错误/恢复记录仅保存到本地数据库。没有远程传输或“已上传云端”状态。

Schema13新增`local_versions`、`local_restores`、`snapshot_meta`、`local_snapshot_events`及索引。沿用原迁移入口：升级前用SQLite在线备份，增量DDL可重复执行。事件表追加保存状态转换、失败原因、暂存标识，重试成功不会抹去失败历史；界面读取最近500项，数据库保留完整事件。原项目、模块、编号、作废记录、历史、计数器没有更新语句。

用Phase 2D实际DDL的无数据Schema12夹具建虚构旧库，验证升级备份仍为12、升级后13、完整性通过、原业务表逐行一致、再次迁移无副作用；原Schema11兼容测试继续验证旧记录及备份。只运行隔离库和自行生成的旧库副本，没有迁移正式数据库。回退源码不能直接读新增版本功能；恢复Schema12备份会失去13后的记录，勿当作通用降级方案。整体归档库迁移/数据库丢失后的灾难恢复仍待3B。

## 状态机和事务边界

1. 后台冻结选择及来源身份、哈希，事务登记`prepared`；任务ID绑定冻结清单/标签/说明，改变后必须新任务。
2. 每项目跨进程非阻塞锁；并发执行受控拒绝。生成应用归属的独立随机暂存目录，登记`copying`，分块独立复制，不用硬链接/符号链接。
3. 比较读取前后文件身份、大小、修改时间和内容，复核全部源文件及归档副本；写完整清单，文件`flush/fsync`，SQLite FULL同步登记`sealed`和清单哈希。
4. 同一文件系统排他目录重命名，禁止覆盖目标；文件系统提交与数据库提交是两个独立边界。随后登记`committed → complete`及字节通过。
5. 故障可留下`failed/cancelled`或已提交待登记任务。重启不会自动重写文件；用户恢复时验证所属标记/清单/全部内容。已有完整目录只补登记，不重新依赖当前工作文件；未封存半成品使用新暂存尝试，原失败产物保留。封存未提交先复核源文件再提交。半成品不列为完整版本。

取消只在提交前生效；提交后继续校验/登记，不删除成功版本或伪报取消。终止拒绝已提交目录。尚未登记到数据库的准备前故障没有版本，重试同ID可创建一次。文件提交完成但数据库失败由任务恢复补登记；已完成数据库对应文件缺失/损坏则校验失败，不能伪报成功。

普通逐文件复制不能证明整套CAD处于同一时刻；创建前需停止编辑。已冻结文件在读取/复制及提交前检查有变化即失败；不声称能防止其他进程精心回写同样内容/元数据或恶意并发替换路径。中断测试是进程崩溃恢复验证，**不是实际断电/存储介质持久性认证**。

## 恢复与路径保护

先完整校验归档，再在目的父目录创建自有暂存，逐文件复制、哈希复核及写入完成凭据；将payload排他提交为新的目的目录，再复核全部文件并登记完成。目的目录必须尚不存在（比允许已有空目录更严格），父目录必须存在，不与当前工作根/归档库/源码重叠；不覆盖、合并或自动删除任何工程。保留嵌套同名文件，恢复根附加保留名`.mw-restore.json`，标识字节通过/CAD可打开性未验证。恢复中断可明确恢复或终止；已提交目的目录凭据和哈希一致才补登记。

拒绝绝对清单路径、`..`、UNC/网络映射、设备名、ADS、链接/联接/重解析、Windows大小写及NFC冲突、文件/目录前缀冲突；不解压附件、不执行文件。归档库用本地数据库关联的UUID所有权标记，不接管未知非空目录。暂存和最终归档位于同一库，恢复暂存和目的位于同一父目录；提交检查卷身份，跨文件系统拒绝。

保护上限：2000文件，单文件2 GiB，总8 GiB，清单4 MiB，相对路径220字符/32层，单组件255个UTF-16单元，完整路径1024个UTF-16单元；1 MiB分块，写前检查所需大小加16 MiB余量。长路径仍可能受本机Windows策略限制，系统错误明确失败。没有自动清理；重试保留的旧尝试占用额外空间，应由后续归属核验清理工具处理，不能直接递归删除用户目录。网络/磁盘I/O当前调用不可强行打断，取消在分块边界检查；不提供物理I/O硬超时。
