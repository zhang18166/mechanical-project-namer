## 启动和操作

在本阶段工作树按README创建专用虚拟环境、安装已锁定的基础/test依赖：

```powershell
.\scripts\dev_backups.ps1
.\scripts\dev_backups.ps1 -DevRoot <仓库外的开发实例目录>
.\scripts\dev_backups.ps1 -Smoke
.\scripts\restore_library.ps1
.\scripts\restore_library.ps1 -Profile <源开发实例目录> -SessionRoot <独立维护界面配置目录>
.\scripts\test_workbench.ps1
```

主客户端“备份与恢复”打开独立维护窗口。创建前**从托盘退出全部源客户端**，仅隐藏窗口不够；维护窗口不跟随主客户端关闭。也可直接用`restore_library.ps1`，不必先打开旧库或成功初始化主客户端。独立入口显示源配置、备份/恢复目的地、范围/数量/大小/排除项、后台进度、取消、错误、验证结果、新实例启动命令及明确的启动按钮。不会自动切换正式实例。

首版要求源实例已有归档库身份（可先打开项目文件的本地版本入口初始化），只支持单个配套归档根。未初始化或出现多个不一致的归档位置明确拒绝，不猜测搬迁关系。

默认开发配置`%LOCALAPPDATA%\MechanicalWorkbenchDev\phase3b`。维护入口若继承开发环境，另用源配置的同级维护目录，避免缓存嵌入源库；也可明确指定SessionRoot。主数据库损坏/源目录丢失不妨碍先显示维护窗口或验证/恢复已有备份。归档/备份主体无需WebEngine、QtPdf、Node、OCCT或真实CAD。预览按需加载，旧命名/项目文件入口保留。

## 完整范围和隐私

“完整”指**已纳入本地归档的全部完整版本 + 配套业务数据库**，不指整台电脑或未归档的工作目录。数据库整体在线备份，项目、模块、文件ID、编号、使用/作废/预留历史、计数器、版本UUID、终结任务及失败事件全部保留，不能为了隐藏敏感数据删改业务记录。

包含：SQLite一致性副本、归档库身份标记、全部完整版本的owner/manifest/payload、配置白名单、备份格式/ID/日期/应用/Schema/范围/排除项/校验结果，以及所有data文件的相对路径、大小、SHA-256。

配置仅允许`current_project_id`、`current_module_code`、`current_part_type`、`last_window_mode`、`always_on_top`，类型及长度另校验。恢复时新设置强制关闭SOLIDWORKS。排除Windows凭据、API Key/密码/令牌/证书、浏览器数据、缓存/日志/临时文件、其他备份、失败暂存/已提取工作副本、数据库外AI派生记忆文件和其他设置。数据库内的AI记录仍整体保存，不能假定自由文字绝无敏感信息。本轮仅用虚构记录；发现实际凭据字段时拒绝并报告，不删列/删记录。token_usage及input/output_tokens为用量字段，不是认证令牌。

**这是本地未加密的私有备份集**。有哈希不等于可公开，也不是数字签名、来源真实性证明、防篡改存储或冷备份介质认证。整个目录、截图和原始报告不能上传GitHub/云/NAS。

## 格式1

```text
<backup-set>/
  COMPLETE.json           # 最后封存，绑定备份ID及manifest SHA-256
  manifest.json           # 格式/应用/Schema/身份/全目录/逻辑数据库指纹/范围
  data/
    database.sqlite3     # SQLite在线备份API生成，整合已提交WAL内容
    config.json          # 只包含白名单设置
    archive/
      .mw-store.json     # 逻辑store_id原样保留
      versions/<UUID>/owner.json, manifest.json, payload/...
```

清单记录原实例/数据库/归档位置作为**私有历史映射和危险重叠检查依据**；验证/恢复不按这些位置取文件，只读data中的相对路径。Phase3A各版本公开格式清单依然不含源绝对路径，不受此备份格式影响。

校验完整标志/格式、精确文件及目录集合、大小/哈希、SQLite integrity_check和外键、store_id、项目/文件/零件/版本关联、全部完整目录及冻结清单、必需文件、业务记录指纹和兼容范围。拒绝未知清单字段、类型异常、未知触发器/虚拟表、较新/较旧Schema和未验证应用版本。首版仅支持应用1.7.1/Schema13/格式1，不静默迁移、降级或修复备份。

校验只用`mode=ro&immutable=1`、query_only和trusted_schema关闭的SQLite连接，数据库必须是已合并WAL的独立副本；不创建数据库、运行迁移或产生WAL/SHM。数据库与文件校验分开完成，任一不一致均失败。

## 一致性、任务和提交边界

本分支客户端整个会话持有共享库租约；Database连接/迁移及SnapshotService完整操作也在UI以下持有租约。维护使用相同锁文件的独占OS锁（Windows LockFileEx，非阻塞；崩溃由系统释放），拒绝活动客户端/任务，不靠界面按钮或PID文件判断。嵌套连接按引用计数释放，乱序关闭不会提前失去保护。

独占后另以SQLite连接`BEGIN IMMEDIATE`冻结写入，用另一只读连接调用在线backup API，避免在持写事务的同一连接自我等待。外部SQLite未完成写事务也会导致受控拒绝。检查未完成归档/恢复、待处理SW任务；失败未终止也拒绝。已使用/作废/长期预留编号是持久业务记录，不当作正在写入，不删除。协调覆盖本分支客户端及服务；不能约束绕过客户端直接改磁盘的任意程序，复制前后仍复核全部内容和范围。旧客户端不属于本轮已验证的维护协调协议，不要将其指向恢复副本。

备份状态：冻结范围/业务指纹 → 自有随机暂存 → SQLite在线副本 → 分块独立复制归档 → 副本哈希/数据库交叉核对及源复核 → 清单/完成标志 → sealed → 同卷排他目录提交 → complete。SQLite事务与文件系统不是单一原子事务。

任务目录在目的父目录下`.mw-library-job-<UUID>`，有不可接管的owner绑定来源/目的、持久状态、追加失败事件和每次随机尝试。重启可“载入任务日志 → 重试上次任务”；必须保留原任务目录及目的父目录，不支持途中搬动日志。源范围改变则新任务；同内容用新ID/新目的地可新建备份。未封存重试建立新尝试，旧失败产物保留；封存已验证产物可提交，不需要重新回源。封存清单/凭据必须匹配冻结任务，不能掉包。文件提交后但日志未完成时核验已提交目录并补记，不覆盖其他目录。

取消在提交前生效；提交后不得假报取消或删除成功结果。暂存与最终目录同卷、独占重命名，提交跨卷拒绝；源库和备份可以位于不同卷，通过独立复制传输。所有复制/哈希分块，写前检查空间，失败不会显示完整备份或完成恢复；没有自动删除/轮换/清理历史备份及旧暂存。

## 新位置恢复和允许变化

先验证整份备份，复制到目的父目录下的自有暂存，再在**副本**中提交位置重绑定事务，逐表对比允许变化，写恢复完成凭据、复核源备份，最后排他提交新目录。DB提交、完成凭据、目录提交、任务日志为独立可恢复边界。恢复目标必须尚不存在，父目录已存在；不合并已有空/非空目录，不覆盖源库/备份/工作工程/源码或正式配置。

恢复实例沿用开发配置布局（local/roaming/cache/workspace），独立单实例标识；保留原逻辑store_id及所有权标记，不能删除标记接管目录。恢复凭据绑定任务、备份清单及原恢复结果，合法后续写入不要求新数据库仍等于旧数据库的字节哈希。

不要从私有暂存目录手工启动客户端。文件提交后、任务补记前若已手动写入新实例，原恢复结果哈希不再成立，自动补记会拒绝，必须保留现场人工核验；不会覆盖或删除那份目录。已完成任务后正常新增版本属于合法写入，后续按版本校验。

| 允许改变的字段 | 原因及验证 |
| --- | --- |
| local_versions.store_path | 绑定新实例归档位置；版本UUID、冻结request_json/hash、版本清单、文件相对路径均不改 |
| projects.directory / solidworks_part_directory | 清空活动旧工作位置，原值存入snapshot_meta历史映射，阻止自动扫描/保存到旧位置；项目ID/代码/名称/时间/编号不改 |
| project_files.state / error | 标记“工作文件待重新关联”，原file_id/path/record_id等保留；旧路径不会自动重扫、预览或打开 |
| snapshot_meta 的明确列出键 | 当前恢复来源、每次旧/新位置记录、原项目工作目录、旧扫描来源/已终结任务的失效标记；恢复凭据列出准确键清单 |

其他表逐行流式指纹必须完全一致，包括模块、零件、历史、编号预留/计数器、失败事件、SQLite序列和Schema定义。保留local_restores的旧目的地作为历史，禁止从恢复实例重新执行那些旧提取任务；可新建提取任务。

归档版本校验及提取只读新归档路径，与旧工作目录无关。旧项目文件记录可查看来源，但批量重新关联工具未实现；本轮可在项目文件页明确添加新工作文件，为同项目创建新版本，旧记录和历史不丢。字节完整性、CAD装配依赖、GLB/PDF对应关系独立；后两项始终未验证，不因整库恢复升级。

## 边界和容量

拒绝绝对/越界相对路径、设备名、ADS、网络盘、符号链接/联接/重解析点、硬链接、Windows大小写/NFC冲突及文件/目录前缀冲突。源、目的、源码、其他实例/归档/备份不能危险重叠。不会执行/解压附件、启动CAD或联网补文件。

全库上限100000文件、256 GiB总量、32 GiB单文件（含SQLite），元数据JSON64 MiB，相对路径512字符/48层；继承完整路径1024 UTF-16单元上限。归档单版本仍有Phase3A的2000文件/8 GiB/2 GiB单文件限制，不能将其误当作整库容量，也未套用预览32 MiB限制。1 MiB文件块、128页数据库备份步进，创建另留64 MiB空间，恢复预估容量按两倍检查并另留64 MiB以覆盖DB重绑定事务。

元数据还限制10000项目/版本任务/提取任务、100000文件索引/扫描来源、200000 snapshot_meta项/键值总16 MiB、单表200万行/SQLite单行16 MiB。版本及数据库行流式处理，数量超限先拒绝，不把全库加载到Python内存。上限是保护边界，未进行256 GiB负载认证；Windows长路径/文件系统策略仍可能导致明确失败。当前系统I/O调用不可强行打断，取消在块/SQLite步进边界检查，无物理I/O硬超时。
