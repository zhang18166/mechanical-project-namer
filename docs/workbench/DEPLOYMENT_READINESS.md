# 后续HTTPS与部署的待验边界

本轮未实施以下事项：腾讯云、飞牛、Nginx/已有网站、域名、安全组、系统服务、生产Python或公网端口。现有HTTPServer继续仅用于隔离回环验证，增加反向代理并不自动得到生产入口安全。

下一阶段须另行授权并逐项验收：

- 复用账号、授权、服务索引、文件级发布状态机及恢复门禁，为维护中的应用服务器适配接口；不复制另一套编号/项目库，不把串行HTTPServer直接当公网服务。
- 真实HTTPS客户端连接与证书链/主机名校验；不使用verify=False、忽略证书错误或关闭安全验证。服务UUID仍是业务身份，不能代替TLS对端认证。
- 明确可信代理边界，只接受指定代理的Forwarded/X-Forwarded信息；重新验证Host、Origin、重复长度/传输编码、认证头及流式请求边界，不能简单放开现有检查。
- 重新测登录限流、上传空闲/总时限、背压、取消与提交竞争、任务锁、大小/数量/空间与CPU/内存/FD限制；不靠无限提高超时或并发掩盖问题。
- 在新HTTP入口上重跑授权矩阵、多文件断流、确认丢失、硬退出及整体恢复。数据路径、普通运行身份和恢复维护放行仍须受控；日志脱敏和审计留存策略需要单独设计。
- 核实真实服务器的系统及补丁、现有服务、CPU/内存/剩余磁盘、实际带宽、TLS和证书更新、配套备份、外部安全变更台账与回滚方式。既往4核4GB/6Mbps仅作参考，不承诺容量或公网性能。

本机WSL同机演练不等于异地、物理介质损坏或断电认证；30分钟协议测试也不关闭Phase2D图形内存/并发诊断/STEP补丁风险。STEP普通模式继续关闭。本文只列待验任务，不执行下一阶段。
